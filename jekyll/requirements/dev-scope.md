# 개발 범위

## 자르는 순서

기획서가 정해뒀습니다. 위에서부터가 아니라 **아래에서부터** 자릅니다.

```
1순위 컷  ⑨ 모델 벤치마크 · 연출 개선
2순위 컷  ⑧ search_notes 구현      → 인터페이스만 남기고 전량 컨텍스트로
3순위 컷  ⑦ 부가 데이터 수집        → 11.2 핵심 지표는 남긴다
4순위 컷  ⑥ 인스펙터 UI            → 판정 로그는 남기고 화면만 축소
5순위 컷  ③ 손상 3층 중 1층(대사 미세 변형)  ← 유일하게 프롬프트 튜닝이 필요한 항목
── 여기까지가 한계. ①②④⑤와 손상 2·3층은 자르지 않는다 ──
```

> **손상 3층은 1층부터 자른다**
> 구현 난도가 크게 다릅니다 — **충식 소실은 사실상 문자열 처리**이고, **노트 불일치는 기존 노트 시스템의 필드 하나**이며, **대사 미세 변형만 프롬프트 튜닝**이 필요합니다. 효과 대비 비용이 가장 나쁜 1층이 먼저 나갑니다.

## 3주 → 14일 압축

기획서는 3주 기준이고 v1 공개는 9/16, **14일 집중 개발**입니다. 일주일이 빕니다.

| 처리 | 내용 |
|---|---|
| 방어선 ①~⑤ | **유지.** 손대지 않는다 |
| ⑥~⑨ | 압축 대상. Day 7(9/09) 알파에서 남은 분량을 보고 위 컷 순서대로 |
| 12.1 범위 | 하루 = 5~6 비트 → **5 비트 고정**. NPC 3명·텍스트 기반은 그대로 |
| ⑤ 전이 | **착수를 앞당긴다.** 늦추면 짧은 작업이 안 끝나는 게 아니라 아예 시작을 못 한다 |

v1 범위를 먼저 닫고, 그 뒤에 확장합니다.

## 범위 밖 — 논의도 하지 않는다

- **계정 / 로그인 / 프로필** — 12.4 위반 (09-16 이후 과잉 사용 방지용 구글 로그인은 예외. [보안 및 운영 한도]({{ '/docs/requirements/security.html' | relative_url }}) 참고)
- **모바일 네이티브 앱** — 기획서에 없다. 텍스트 웹으로 공개한다
- 게임 세계 바깥을 조회하는 도구 (외부 API·웹 검색·계산기) — 8.7 ③
- 파인튜닝 — "모델 선정 평가"까지만 말한다 (9.4)
- 판정 NPC 5인 확장 — 탐문 경로가 3 → 10으로 늘어 희소성이 깨진다 (4.2-1)
- 손상 4층 이상 (감정 어긋남·인물 기억 겹침 등) — 여유가 있을 때만

> **로그인은 만들지 않는다 (09-03 설계)**
> 이전 문서는 회원가입·로그인·프로필을 MUST 최상단에 뒀습니다. **기획서 12.4와 정면 충돌합니다.** 세션은 익명 식별자로만 잡고, 계정 시스템은 범위 밖입니다. 이 결정으로 Day 3~4 이틀치 작업이 방어선 쪽으로 재배치됩니다.

## 발화 예산 — 설정값으로 분리

> **발화 예산 — 9/07 확정**
> **0장 · 4.3 · 5.1 · 6.1은 6회**, **12.1은 5회(하한 3)**입니다. 다만 12.1은 「구현 범위 (3주)」 챕터이고 같은 절에 "하루 5~6 비트", "NPC 3명" 같은 축소 항목이 나란히 있습니다. **모순이 아니라 층이 다른 것**으로 읽습니다 — 6회는 게임 설계값, 5회는 프로토타입 축소값.
>
> 기획서 스스로 이 수치를 **튜닝 대상**으로 둡니다 (6.1 "수치는 튜닝 대상", 11.1 "난이도 튜닝 근거"). 그래서 상수로 박지 않고 **설정값으로 분리**합니다. 숫자가 무엇이든 구조는 바뀌지 않습니다.
>
> **잠정 기본값 — 초기 5 / 5루프째 4 / 하한 3.** 12.1을 따르되 6.1의 감소 곡선과 하한을 그대로 씁니다. 이 값으로 도메인 테스트를 먼저 박고, 9/07에 확정했습니다.
