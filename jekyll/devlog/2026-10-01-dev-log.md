# 2026-10-01 ERD 문서 추가 (docs/erd.md, 코드 수정 없음)

DB 스키마를 Mermaid ERD로 옮겨 `docs/erd.md`에 저장했다. 근거는 ORM 4개 파일(`backend/apps/engine/adapter/outbound/orms/`)과 마이그레이션 8개, 그리고 개발 DB의 실제 제약 조건이다.

- **구성** — 그림 두 장. 게임 상태·계정·로그 9개 테이블(`users`·`attempts`·`loops`·`npc_states`·`nights`·`notes`·`rules`·`survey_votes`·`events`)과 시나리오 시드 6개 테이블. 실선은 DB 외래 키, 점선은 코드로만 지키는 관계.
- **대조 결과** — 테이블 15개(+`alembic_version`), alembic head `216f290d03b3`. 외래 키는 5개뿐(`loops`·`notes`·`rules` → `attempts`, `npc_states`·`nights` → `loops`)이고 `attempts.user_id`·`prior_attempt_id`, `survey_votes.attempt_id`·`user_id`, `events.session_id`에는 외래 키가 없다.
- **적어 둔 주의점** — `events.session_id`는 보통 `attempts.id`지만 정원·한도 가드에 막힌 요청은 일회용 UUID로 남는다(`session_interactor.py:43`). `truth_claim_embeddings`는 스키마만 있고 런타임에서 쓰지 않는다.
- **검증** — Mermaid 11.17.2 파서로 두 블록 문법 통과. 실제 렌더 화면은 확인하지 않았다.

### 백엔드 로그 누적 (`backend/uvicorn-8500.log`, 09-24 기동 이후 전체)

09-24 일지 때 23줄이던 로그가 196줄이 됐다. uvicorn 접근 로그에는 시각이 없어 어느 줄부터가 오늘인지는 가릴 수 없다. 확실한 것은 마지막 줄이 오늘 22:39:04에 적혔다는 것뿐이다. DB에서 오늘 만들어진 판 수를 세어 보려 했으나 조회 승인이 나지 않아 못 했다.

| 응답 | 건수 |
|---|---|
| 200 | 81 |
| 307 | 33 |
| 401 | 18 |
| 404 | 57 |
| 503 | 3 |

- **마지막 기록(22:39)** — 구글 로그인 한 건. `POST /sessions` 401 → `auth/google/start` 307 → `google/callback` 307 → `POST /sessions` 200 → `POST /sessions/{id}/loops` 200 → `observations` 200 → `npcs` 200. 판 시작까지 정상이다.
- **누적 판 시작** — `POST /sessions` 200이 7건.
- **NPC 대화** — `POST /loops/{id}/utterances` 200이 11건, 503이 3건. 503은 71~73줄에 한 회차에서 연속으로 났고 그 뒤 다른 회차의 대화는 200이다. 로그에 traceback·error 줄이 0이라 원인은 로그만으로 알 수 없다. 09-27 점검 때의 세션 기록(claude-mem 관찰 목록)에 이미 잡혀 있던 것으로, 오늘 생긴 것은 아니다. 원인 조사는 하지 않았다.
- **밤 흐름** — 바로 앞 판에서는 `beats/next`·`paw/respond`·`night/draft`·`nights/{id}/submit`·`nights/{id}/questions` 3건·`options`가 전부 200이다. 낮 대화부터 밤 답안·신의 질문·선택지 조회까지 간 기록이고, 그 뒤 요청은 로그에 없다.
