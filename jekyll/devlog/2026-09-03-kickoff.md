# 2026-09-03 킥오프 — 14일 안에 무엇을 어떻게 끝낼 것인가

## 오늘 정한 것

9월 16일 v1 공개까지 **14일**입니다. 오늘 킥오프에서 정한 것은 세 가지입니다.

### 1. 날짜는 고정, 범위는 유동

v1 공개일은 9/16로 둡니다. 그래서 조절 변수는 **만들 것의 양** 하나뿐입니다.
Day 7(9/09) 알파 시연에서 남은 분량이 감당 안 되면 그날 저녁에 잘라냅니다.
무엇부터 자를지는 [범위 문서]({{ '/docs/requirements/dev-scope.html' | relative_url }})에 **미리 순서를 정해뒀습니다.**
그 자리에서 고민하면 반나절이 날아가기 때문입니다. v1 범위를 먼저 닫고, 잘라낸 것은 공개 이후에 확장합니다.

### 2. 9/04 에 ERD 와 API 계약을 얼린다

이게 이번 일정의 핵심 장치입니다.
계약이 나오기 전까지는 화면 껍데기밖에 못 만듭니다.
**계약이 나오는 순간 백엔드·프론트·AI 에이전트 작업을 번갈아 달릴 수 있습니다.** 혼자 만들더라도 계약이 먼저 있어야 세 영역이 서로를 기다리지 않습니다.

완벽한 계약을 기다리지 않습니다. 9/04 에 v1 을 내고, 통합에서 어긋나는 건 Day 5(9/07) 에 고칩니다.

### 3. `done` 은 완료 기준을 확인한 뒤에만 붙인다

"다 했다"의 기준은 그때그때 흔들립니다.
어떤 날은 로컬에서 되는 것이고, 어떤 날은 스테이징에서 끝까지 되는 것입니다.

그래서 카드는 `review` 까지만 올려 두고, 저녁에 카드의 **완료 기준(DoD)** 을 직접 확인한 뒤
`done` 으로 내립니다. 작업 중의 판단과 확인의 판단을 시간으로 분리하는 장치입니다.

## 지금 막혀 있는 것

**기획서 v6 와 컨셉 영상이 이 레포에 없습니다.**
둘 다 로컬(macOS)에만 있어서, 지금 사이트의 서비스 정의·기능 목록·디자인 토큰은
`com.remakeday` 레포의 실제 구조에서 역으로 정리한 것입니다.

이걸 기다리며 멈추지는 않습니다. 대신:

- 기획과 **무관하게 확정적인 것**부터 소진합니다 — 인증, 인프라, 백엔드 구조, 디자인 시스템 골격
- 오늘(Day 1) 안에 기획서를 레포에 넣습니다
- Day 2 까지 안 되면 **5개 항목**(사용자·문제·해법·핵심기능 3개·화면 5개)을 먼저 확정 선언합니다

[리스크 R1]({{ '/docs/schedule/risk.html' | relative_url }})로 등록했습니다.

## 오늘 할 일

오늘 카드는 16건입니다.
오늘의 관문은 **ERD 초안 + API 계약 v0 + 레포·인프라 스켈레톤이 전부 올라가는 것**입니다.

오늘 정한 규약(네이밍·브랜치·API 계약)은 9/16 까지 바꾸지 않습니다.
14일 동안 규약을 다시 논의하는 시간이 곧 기능을 못 만드는 시간입니다.
