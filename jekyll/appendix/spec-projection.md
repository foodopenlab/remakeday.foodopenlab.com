# 기획서 반영표

처음 보는 사람이 5분 안에 무엇을 만드는지 알게 하는 것이 목표입니다.

> **이 문서의 근거**
> `REMAKE_DAY_기획서_v6.md`(2026-09-02 갱신) 전문. 기획 10편의 「추론」 표시와 달리 **여기 있는 내용은 전부 기획서에 확정으로 적혀 있는 것**입니다. 다만 마지막 섹션의 [기획서 v6 반영 결과](#gap)는 재작성 전후의 차이를 남겨 둔 기록입니다.

## 1 · 한 문장이면 이렇다

> **"같은 하루를 반복하는데, 나만 그걸 기억한다. 그리고 그 사실을 말할 수 없다."**

| | 내용 |
|---|---|
| 하루가 끝나면 죽는다 | 그리고 아침으로 돌아간다. 기억하는 건 나뿐 |
| 할 수 있는 건 말뿐 | 전투도 이동도 없다. 하루 6마디 |
| 정확히 말하면 의심받는다 | 아는 티를 내는 순간 진다 |

## 2 · 하루가 도는 모양

이 원이 게임의 전부입니다. 유저는 이 원을 수십 번 돕니다.

| 단계 | 무엇 | 비고 |
|---|---|---|
| **7:12** 눈을 뜬다 | 매 루프 고정 문장 | 시작 |
| 대화한다 | 6마디. 쓰면 줄어든다 | 유일한 행동 |
| NPC가 움직인다 | 각자 판단해서 | 대본 없음 · LLM |
| 죽는다 | 사고가 아니다. 누군가의 선택 | 끝 → **되감기** |

| 되감길 때 지워지는 것 | 남는 것 |
|---|---|
| NPC 기억 · 신뢰 · 의심 | 내 노트 · 세계 손상 |

> **여기가 이 게임의 심장입니다.** 정보는 쌓이는데(내 노트) 관계는 매번 0으로 돌아갑니다(NPC 신뢰). 그래서 마지막 루프에서 유저는 *가장 많이 아는 상태로, 가장 적은 말로, 처음부터* 관계를 쌓아야 합니다.

## 3 · 말할 때마다 두 개가 동시에 정해진다

얼마나 **알려줄지**(전달량), 그리고 내가 안다는 걸 얼마나 **들킬지**(노출량). 이 두 개가 따로 놉니다.

| 전략 | 예 | 전달량 | 노출량 | 결과 |
|---|---|---|---|---|
| ✗ 직접 말하기 | "3시에 그 사람 만나지 마" | 높음 | 높음 | 의심받는다 — **의심 구역** |
| △ 애매하게 말하기 | "그 사람 요즘 좀 이상하지 않아?" | 낮음 | 낮음 | 안전하다 · 근데 아무 일도 안 일어난다 |
| ◎ 출처를 빌린 진실 | "어제 준이 네 얘기 물어보더라" | 중간 이상 | 낮음 | **핵심 기술 구역.** 단, 준에게 확인이 들어가면 들통난다 — 도박이다 |

> **이게 왜 중요하냐면** — NPC는 `ask_npc`라는 도구로 *실제로 준에게 물어봅니다.* 프롬프트에 "거짓말을 간파하라"고 적는 게 아니라, 진짜 호출이 일어나고 준의 의심도가 올라갑니다. **A를 속인 비용이 B에게 청구됩니다.**

## 4 · 사람은 다섯, 판정은 셋

| 인물 | 층위 | 한 줄 | 설명 |
|---|---|---|---|
| **민석** | 핵심 | 루프를 **기억한다** | 유저보다 수백 번 더 갇혀 있었다. 반복할수록 세계가 닳는 걸 안다. 그래서 유저를 막는다. **메모리 정책 예외 — 유일하게 기억이 유지되는 NPC** |
| **채연** | 핵심 | 아무것도 모른다 | 민석에 의해 움직여질 수 있다 |
| **은상** | 핵심 | 아무것도 모른다 | 불안해지면 위험해진다 |
| 준 | 주변 | 편하게 말한다 | 정보원이자 **이름이 빌려지는 자리** |
| 충식 | 주변 | 오늘 자리에 없다 | 대사가 한 줄도 없다. 그런데 손상 연출의 **마지막 단계**를 맡는다 |

> **왜 셋만 판정하나** — 다섯이면 탐문 경로가 3개에서 10개로 늘고, 그만큼 발화 예산을 늘려야 합니다. 그러면 "말이 희소하다"는 전제가 깨지고 게임이 아니게 됩니다.

## 5 · 살려고 발버둥칠수록 세계가 닳는다

게이지도 숫자도 안 보여줍니다. 현상으로만 나타납니다. **알아차리는 것 자체가 플레이입니다.**

| 층 | 시기 | 현상 | 유저에게 |
|---|---|---|---|
| 1층 | 초반 | 대사가 미세하게 다르다 | 확인할 방법이 없다. 착각인지 모른다 |
| 2층 | 중반 | 노트가 현실과 안 맞는다 | 내 유일한 무기를 못 믿게 된다 |
| 3층 | 후반 | 충식이 사라진다 | "충식이요? 누구요?" |

손상은 **루프 횟수**가 아니라 **개입 깊이**에 비례한다 — 많이 돌아도 되지만, 깊게 말하면 닳는다.

> **잘라야 하면 1층부터.** 충식 소실은 사실상 문자열 처리(비용 0, 효과 최대), 노트 불일치는 필드 하나, 대사 미세 변형만 프롬프트 튜닝이 듭니다.

## 6 · 끝나는 방법은 네 가지

| 엔딩 | 알아냄 | 믿게 함 | 설명 |
|---|---|---|---|
| **반복** | ✗ | ✗ | 다시 루프 |
| **고립** | ○ | ✗ | 진실을 알았지만 아무도 믿지 않았다 |
| **망설임** | ✗ | ○ | 죽었지만, 민석은 마지막에 멈칫했다 |
| **인계** | ○ | ○ | 민석이 수백 번 만에 혼자가 아니게 되었다 |

> **유저가 이기는 게 아닙니다.** 민석이 옳았을 수도 있다는 건 끝까지 부정되지 않습니다. 다만 그가 *혼자 결정할 필요가 없어졌을 뿐*입니다. 이 게임에 악당은 없습니다.

## 7 · 그래서 화면은 이렇게 생겼다

3주 안에 만들 것은 **딱 다섯 장**입니다. 전부 텍스트 기반입니다.

| # | 화면 | 보이는 것 | 메모 |
|---|---|---|---|
| ① | 아침 화면 — 첫인상 | `7시 12분. 눈을 뜬다.` / `천장이 조금 낮아 보인다.` | 손상 1층은 두 번째 문장부터 |
| ② | 대화창 | 민석: 오늘은 좀 일찍 왔네. / 나: 어제 준이 네 얘기… / `남은 4/6` | 발화 예산 상시 표시 |
| ③ | 루프 노트 — 대표 캡처 후보 | 🔍 "물 냄새"로 검색 / L1 아무것도 모른 채 / L2 3시, 물 냄새 / L3 3시, 계단, 물 / L4 노트와 현실 불일치 | 루프가 쌓일수록 촘촘해진다 |
| ④ | 인스펙터 — 게임으로는 미스터리, 기술로는 완전한 인과 추적 | 아래 체인 | 거짓말이 왜 들통났는지가 전부 열린다 — 블랙박스가 아니다 |
| ⑤ | 침묵 권고 배너 | 권고: 지금은 말하지 마세요 / 근거 · 최근 3턴 의심도 +14 / 근거 · 신뢰 회복 이벤트 없음 / 상태 · 의심 52 / 임계 60 / [따른다] [무시한다] | 여기서만 AI가 제안자다. 나머지 전부에서는 사람이 설득자, LLM이 저항자. 수용/무시가 로그에 남는다 = 지표 |

```
발화: "어제 준이 네 얘기 물어보더라"
의심 판정   → 의심도 +5   (누적 41 / 임계 60)
도구 호출   → ask_npc(준, "유저 얘기")  [예산 2→1]
도구 결과   → "없음" · 부작용: 준.의심도 +6
불일치 판정 → 의심도 +15  (누적 56 / 임계 60)
신뢰 판정   → 변화 없음 (비용 없는 발화)
재계획      → 트리거: 탐문 불일치 / 수정 없음 (임계 미달)
출력: "그래? …준이 그런 말을 했다고."
```

## 8 · 안쪽은 엔진 하나, 바깥은 도메인 셋

게임은 이 엔진의 **첫 번째 도메인**일 뿐입니다. 그게 이 프로젝트의 채용 어필 포인트입니다.

**BeyondBob Engine** — 도메인이 바뀌어도 이 안쪽 코드는 안 바뀐다.

| 구성 요소 | 역할 |
|---|---|
| Planner | 하루 계획 |
| Agent | 매 발화 판단 |
| Re-plan ★ | 계획 수정 |
| Evaluator | 루프 결산 |
| Memory | 비대칭 |
| 도구 2개뿐 | `ask_npc` · `search_notes` |
| 포트 3개뿐 | LLM 교체 · 도구 등록 · 도메인 전이 |

도메인 어댑터만 갈아 끼운다.

| 도메인 | 개념 | 비고 |
|---|---|---|
| **REMAKE DAY** | NPC · 의심도 · 발화 예산 · 루프 · 죽음 | 주 제품 |
| **감사 대응** | 감사관 · 설득 저항 · 면담 턴 · 기각 | 주 시연 · 30초 |
| 커리어 대화 | 성과 면담 · 이견 제기 · 프롬프트 하나 | 보조 시연 · 5초 |

> **같은 인스펙터가 다른 도메인에서 열리는 장면**이 시연의 전부입니다. 어댑터 하나는 우연일 수 있지만 둘이면 구조라서, 커리어 대화가 5초짜리인데도 들어갑니다.

## 9 · 무엇부터 만드나

위 다섯이 없으면 v1에 포함하지 않는다고 기획서가 못박았습니다. 아래 넷은 시간 나면 하는 것입니다.

| 순위 | 항목 | 메모 |
|---|---|---|
| **1** | 대화 + 의심/신뢰 판정 + `ask_npc` | 저항 층 — 셋을 한 덩어리로. 도구가 빠지면 거짓말이 검증 불가능해진다 |
| **2** | 침묵 권고 + 수용/무시 로깅 | 에이전트 층 + 측정 층 — 사람이 AI를 믿는지 재는 유일한 지점 |
| **3** | 루프 + 노트 축적 + 손상 3층 | 서바이벌 감각의 전부 — 빠지면 반복이 그냥 재시도가 된다 |
| **4** | 민석 예외 계층 + 정체 발현 | 새 시스템이 아니라 정책 분기 하나 |
| **5** | 도메인 어댑터 교체 시연 | 코어가 돌면 짧은 작업. 늦추면 시작조차 못 한다 |
| 6 | 인스펙터 + 아키텍처 CI | |
| 7 | 나머지 데이터 수집 | |
| 8 | `search_notes` | 인터페이스만 뚫어두고 구현은 미룬다 |
| 9 | 모델 벤치마크 · 연출 개선 | |

> **⑤ 전이 시연에 주의.** 기획서가 명시적으로 경고합니다 — *"코어가 돌기 시작하면 즉시 첫 어댑터를 시도한다. 그때 막히면 도메인 개념이 코어로 새어 들어간 것이므로 고칠 시간이 있다. 3주차에 발견하면 고칠 수 없다."* 순서상 5번이지만 **착수는 빨라야 합니다.**

## 10 · 기획서 v6 반영 결과 {#gap}

기획 10편과 작업 보드는 **기획서가 도착하기 전 코드베이스를 보고 쓴 것**이라 제품 정의부터 틀렸습니다.
2026-09-03에 원문 기준으로 전면 재작성했습니다. 아래는 무엇이 어떻게 바뀌었는지 남겨 둔 기록입니다.

| 항목 | 재작성 전 (추정) | 현재 = 기획서 v6 원문 |
|---|---|---|
| 제품이 뭔가 | 식(食) 도메인 서비스 | 루프물 대화 **게임** REMAKE DAY |
| BeyondBob | 첫 번째 제품 이름 | **엔진 이름** · 게임·감사·커리어가 공유 |
| 맥락 | 기재 없음 | 개인 프로젝트 · 로그인 없는 공개 서비스로 오픈 |
| 클라이언트 | 웹 + 모바일 앱 2종 | 텍스트 화면 5장 · 로그인/설치 없이 즉시 진입 |
| 우선순위 | MoSCoW · 자체 컷 순서 | 절대 방어선 ①~⑤ (12.3) |
| AI 설계 | 일반 에이전트 아키텍처 | Planner/Agent/Advisor/Re-plan/Evaluator + 도구 2개 + 민석 메모리 예외 |
| 데이터 | 일반 ERD (계정·프로필·파일) | 판정 로그 · 수용/무시 필드 · 세계 손상 · 익명 세션 |
| 인증 | 회원가입·로그인이 MUST 최상단 | **만들지 않는다** — 12.4 즉시 진입과 충돌 |
| 기간 | 14일 (9/03 → 9/16) | 기획서는 3주 · **14일 유지** |

> **기간만 기획서를 따르지 않습니다.** 14일 집중 개발 후 9/16에 v1을 공개하기로 잡았으므로 3주 설계를 14일에 넣습니다. 그 차이는 방어선 ①~⑤를 지키고 ⑥~⑨를 [컷 순서]({{ '/docs/requirements/dev-scope.html' | relative_url }})대로 줄여 흡수합니다 — [리스크 R2]({{ '/docs/schedule/risk.html' | relative_url }}).
