# 검수 체크리스트

매일 아침·저녁에 그대로 따라 읽는 목록입니다. 14일 내내 같은 절차를 반복했습니다.

## 아침 09:30 (10분)

- [ ] 오늘 할 일 목록을 띄운다
- [ ] **당일 관문(Gate)** 을 소리 내어 읽는다 — 오늘 뭘 통과해야 하는지 한 문장으로 고정한다
- [ ] 어제 끝낸 것 / 오늘 `doing` 으로 잡을 카드를 정한다 (동시에 2건까지)
- [ ] 어제 **반려된 카드**가 있으면 오늘 어떻게 처리할지 정한다
- [ ] 어제 저녁 **숙지 항목**(계약·규약 변경)을 다시 읽고 영향받는 코드를 확인한다
- [ ] 오늘의 **선행 의존**을 짚는다 (예: 웹의 로그인 화면 ← 인증 API)
- [ ] 막힌 것이 있으면 **언제 어떻게 풀지** 그 자리에서 정한다

## 낮

- [ ] 오늘자 카드 진행
- [ ] 스테이징 헬스체크 1회 확인
- [ ] CI 실패 알림이 왔으면 즉시 처리
- [ ] Day 6 이후: LLM 일일 비용 + 역할별 스키마 통과율 확인
- [ ] 막힘이 생기면 다른 일을 멈추고 그것부터 푼다

## 저녁 18:00 (30분)

### 확인 (15분)

- [ ] `review` 상태 카드를 하나씩 연다
- [ ] 카드의 **완료 기준(DoD)** 을 읽고 **직접** 확인한다
      (API 는 요청을 날려보고, 화면은 눌러보고, AI 는 대화를 걸어본다)
- [ ] 통과 → `status: done`
- [ ] 미충족 → `status: doing` + `note:` 에 반려 사유 한 줄

### 갱신 (5분)

- [ ] 칸반 YAML 수정 후 커밋·푸시
- [ ] 새로 생긴 업무가 있으면 카드를 **추가**한다 (id 는 접두사 + 다음 번호)
- [ ] 오늘 못 끝낸 카드는 **날짜를 미루지 말고** 그대로 둔다 — 지연이 보여야 한다

### 숙지 (10분)

- [ ] 오늘 `done` 중 **다른 영역에 영향 있는 것**을 고른다
      (API 계약 · 데이터 모델 · 디자인 토큰 · SSE 규약 · 환경 변경)
- [ ] 개발일지 1편을 쓴다 — 무엇이 확정됐고, **다음에 무엇을 해야 하는지**
- [ ] 내일 관문의 **선행조건이 준비됐는지** 점검. 안 됐으면 밤에 처리하거나 내일 아침 첫 안건으로
