# 주요 내용

## 이름 두 개를 구분한다

| 이름 | 무엇인가 |
|---|---|
| **REMAKE DAY** | 게임 타이틀 |
| **BeyondBob Engine** | 코어 엔진. 어댑터 위 계층 전부. 게임·감사 대응·커리어 대화가 **공유**한다 |

> **BeyondBob은 제품명이 아니라 엔진 이름입니다**
> 도메인을 교체해도 이 경계 안쪽 코드는 바뀌지 않습니다. 전이 시연(10장)의 근거가 여기에 있습니다.

엔진의 계층 구조와 포트는 [시스템 아키텍처]({{ '/docs/high-level-design/architecture.html' | relative_url }})에 있습니다.

## 세계관 — 확정 사항

- 유저는 하루의 끝에 죽고 아침으로 돌아온다. **유저만 기억한다**
- **민석이 루프 인지자다.** 유저보다 오래 갇혀 있었고, 반복할수록 세계가 닳는다는 것을 안다
- 민석이 막는 이유는 **세계 보존**이며, **그가 옳을 수도 있다.** 이 게임에 악당은 없다
- 클리어 조건은 민석이 수백 번 동안 하지 못한 일을 대신 해내는 것 — **나머지에게 진실을 믿게 만드는 것**
- 아침 고정 문장 — **"7시 12분. 눈을 뜬다."**

## 등장인물 — 판정 3인 + 주변 2인

| 이름 | 층위 | 역할 |
|---|---|---|
| **민석** | 핵심 | **루프 인지자.** 기억하며, 세계가 닳는 것을 알고, 유저를 막으려 한다 |
| **채연** | 핵심 | 아무것도 모른다. 민석에 의해 움직여질 수 있다 |
| **은상** | 핵심 | 아무것도 모른다. 불안해지면 위험해진다 |
| 준 | 주변 | 편하게 말한다. 유저의 정보원이자 **이름이 빌려지는 자리** |
| 충식 | 주변 | 오늘 자리에 없다. 이름만 언급되며 등장하지 않는다 |

**판정 대상은 셋으로 고정합니다.** 다섯이면 탐문 경로가 3개에서 10개로 늘고,
발화 예산을 늘려야 하므로 희소성이 깨집니다.

충식은 대사가 한 줄도 없지만 **손상 연출의 최종 단계**를 담당합니다.

## 사용자 — 3층

| 층 | 누구 | 무엇이 없어서 오는가 |
|---|---|---|
| **1차** | 에이전트 제품을 만드는 개발자 | 자기 제품에 붙일 **"거절할 줄 아는 사용자"가 없다.** LLM 페르소나는 무엇을 시켜도 협조한다 |
| **2차** | 하기 어려운 말을 앞둔 실무자 | 되돌릴 수 없는 대화는 연습이 불가능하다 |
| **3차** | 게임을 하지 않는 사람 | 반사신경·복잡한 조작·긴 시간이 필요 없는 텍스트 추론 |

1차 사용자에게 제공하는 것은 **저항이 상태로 모델링된 대화 환경**입니다.
저항·신뢰·발화 예산이 명시적 수치이므로 **어느 지점에서 설득이 실패했는지 지목**할 수 있고,
판정 로그가 전부 열립니다.

> **인스펙터는 게임의 부산물이 아니다**
> 11장의 실험 설계·인스펙터·판정 로그 개봉은 1차 사용자가 **필요로 하는 기능 그 자체**입니다. "게임에 곁들인 디버그 화면"으로 취급하면 안 됩니다.

## 절대 방어선 ①~⑤ — 요약

기획서 12.3이 정한 우선순위입니다. 이 다섯은 **협상 대상이 아니며**, 다섯이 없으면 v1에 포함하지 않습니다.

| 순위 | 항목 | 한 줄 요약 |
|---|---|---|
| **①** | 대화 + 의심/신뢰 판정 + `ask_npc` | 탐문 도구가 없으면 "거짓 출처를 빌린 진실"이 검증 불가능해진다 |
| **②** | 침묵 권고 + 수용/무시 로깅 | 측정 ②(사람이 AI를 믿는 정도)가 여기서만 나온다 |
| **③** | 루프 + 노트 축적 + 손상 3층 | 세계가 닳는 게 안 보이면 반복이 단순 재시도가 된다 |
| **④** | 민석 예외 계층 + 정체 발현 트리거 | 새 시스템이 아니라 메모리 정책 분기 |
| **⑤** | 전이 시연 (도메인 어댑터 교체) | 코어가 완성돼 있으면 짧은 작업. 늦추면 시작을 못 한다 |

⑥ 인스펙터 + 아키텍처 CI, ⑦ 나머지 데이터 수집, ⑧ 노트 검색, ⑨ 모델 벤치마크·연출 개선은 아래에서부터 자르는 압축 대상입니다.
전체 표와 컷 순서는 [목적]({{ '/docs/requirements/purpose.html' | relative_url }})과 [개발 범위]({{ '/docs/requirements/dev-scope.html' | relative_url }})에 있습니다.
